# Crow Station — بطاقات القرارات

> سجل إجابات صاحب المشروع بحسب قالب القسم 9 في [ملف التسليم](TEAM-HANDOFF.ar.md). المعرفات مطابقة للنسخة الإنجليزية `DECISION-CARDS.en.md` على فرع plan-en.

تُضاف بطاقة لكل سؤال يُحسم. لا تُحذف البطاقات القديمة؛ إذا تغيّر قرار تُضاف بطاقة جديدة وتُحدَّث حالة القديمة إلى «مستبدل».

## H-Q01 — أثر تحديث الدرس على الإكمال

| الحقل | القيمة |
| --- | --- |
| المعرف | H-Q01 ← القرار H-D39. مرتبط بـ D-03 وD-10 وH-D06. |
| السؤال المطروح | المدرس حدّث درساً مجاناً بعد أن أكمله الطالب. ماذا يحدث لتقدّم الطالب في هذا الدرس؟ (الشهادات الصادرة قبل التحديث تبقى صالحة في كل الخيارات.) الخيارات: يبقى مكتملاً مع تنبيه / المدرس يحدد نوع التحديث / أي تحديث يلغي الإكمال / يُعاد الاختبار فقط. |
| نص إجابة صاحب المشروع | اختار: «يبقى مكتملاً مع تنبيه (موصى به)». |
| تاريخ الإجابة والتوثيق | الإجابة: 29 أكتوبر 2026. التوثيق: 29 أكتوبر 2026. |
| الحالة | متفق عليه. |
| الصياغة التشغيلية | عندما ينشر المدرس نسخة محدَّثة من درس، وكان الطالب قد أكمل الدرس، يبقى الدرس مكتملاً للطالب، ويظهر له تنبيه بأن الدرس تحدّث، ومراجعة النسخة الجديدة اختيارية. |
| القرار السابق المتأثر | لا يوجد إلغاء. يكمل H-D06 (التحديث مجاني ولا يفقد المشتري المحتوى). |
| الاستثناءات وما لم يُحسم | شكل التنبيه وقناته؛ أثر التحديث على درس بدأه الطالب ولم يكمله؛ تعريف الإكمال نفسه (H-Q12). |
| أثر البيانات والصلاحيات والمال | مقترح: يُسجَّل الإكمال مع نسخة الدرس التي أُكملت، وتُضاف حالة «محدَّث بعد إكمالك» لعرض التنبيه. لا أثر مالي. |
| مثال قبول | عند أن يكمل الطالب درساً، ثم ينشر المدرس نسخة محدَّثة منه، تكون النتيجة: الدرس يظهر مكتملاً، ونسبة إكمال الكورس لا تتغير، ويظهر تنبيه «تم تحديث هذا الدرس». |
| المراجعة | أعدّ البطاقة Claude بطلب صاحب المشروع. لم يُحدَّد مراجع. اعتمد القرار صاحب المشروع. |
| مواضع التحديث | ملف التسليم 4.3 و7 و12؛ وثيقة المنتج 6.1 و7؛ تخطيط البيانات 5 وD-03 وD-10؛ النسخة الإنجليزية. |

## H-Q02 — الدرس في أكثر من كورس

| الحقل | القيمة |
| --- | --- |
| المعرف | H-Q02 ← القرار H-D40، ويستبدل H-D09. مرتبط بـ D-03 وD-10 وH-D08 وH-D10. |
| السؤال المطروح | الدرس الواحد يمكن أن يظهر في أكثر من كورس (H-D09). إذا أكمله الطالب في كورس (أ) وهو مشترك أيضاً في كورس (ب) الذي يظهر فيه الدرس نفسه، هل يُحسب مكتملاً في (ب) أيضاً؟ |
| نص إجابة صاحب المشروع | «لا يمكن أن يكون الدرس في أكثر من كورس، وإذا صدف ذلك فكل كورس تقدّمه الخاص.» ثم قال عن H-D09: «لا أذكر أنني أجبت عن هكذا أمر». بعد شرح بمثال (مدرس يحتاج درس «تثبيت بايثون» في كورسين) اختار: «الطريقة 2: نسخ مستقل». |
| تاريخ الإجابة والتوثيق | الإجابة: 29 أكتوبر 2026. التوثيق: 29 أكتوبر 2026. |
| الحالة | متفق عليه. |
| الصياغة التشغيلية | ينتمي كل درس إلى كورس واحد فقط. إذا أراد المدرس المحتوى نفسه في كورس آخر، ينسخ الدرس، فتنشأ نسخة مستقلة لها تقدّمها وتحديثاتها الخاصة. تعديل إحدى النسختين لا يغيّر الأخرى، والطالب يكمل كل نسخة داخل كورسها. |
| القرار السابق المتأثر | H-D09 («يمكن استخدام الدرس نفسه في عدة كورسات») أصبح مستبدلاً. لم يتذكر صاحب المشروع تلك الإجابة، ولا يحفظ المستودع نصها الأصلي. لا يتغيّر H-D08 (نقل الدرس) ولا H-D10 (سعر كل كورس مستقل). |
| الاستثناءات وما لم يُحسم | من يملك النسخة عند نقل ملكية الكورس؛ هل تُنسخ الاختبارات والمرفقات تلقائياً؛ هل يُسمح بنسخ درس بين مدرسين مختلفين. |
| أثر البيانات والصلاحيات والمال | مقترح: علاقة الدرس بالكورس واحد إلى واحد، مع حقل اختياري يشير إلى الدرس الأصلي المنسوخ منه. التقدّم يُسجَّل لكل درس، وبالتالي لكل كورس. لا خصم بين الكورسات (H-D10). |
| مثال قبول | عند أن ينسخ المدرس درس «تثبيت بايثون» من كورس «أساسيات بايثون» إلى كورس «تحليل البيانات»، وكان الطالب قد أكمله في الأول، تكون النتيجة: الدرس يظهر غير مكتمل في الكورس الثاني، وتعديل نسخة الكورس الأول لا يغيّر نسخة الثاني. |
| المراجعة | أعدّ البطاقة Claude بطلب صاحب المشروع. لم يُحدَّد مراجع. اعتمد القرار صاحب المشروع. |
| مواضع التحديث | ملف التسليم 4 و4.3 و5 و7 و12؛ وثيقة المنتج 6.1؛ تخطيط البيانات 5 وD-03؛ النسخة الإنجليزية. |

## H-Q03 — شكل بيع الإضافة المدفوعة

| الحقل | القيمة |
| --- | --- |
| المعرف | H-Q03 ← القرار H-D41. مرتبط بـ H-D07 وH-D10 وO-03 وD-03. |
| السؤال المطروح | قررت سابقاً (H-D07) أن المدرس يمكنه بيع «إضافة» مدفوعة خارج محتوى الكورس الموعود، وأن بيع درس أو قسم منفرد ممنوع (H-D10). مثال: بعد كورس «أساسيات بايثون» يريد المدرس بيع «10 تمارين محلولة إضافية». بأي شكل تُباع هذه الإضافة؟ الخيارات: إضافة مرتبطة بالكورس / منتج مستقل لأي أحد / تُنشر ككورس جديد / لا إضافات مدفوعة. |
| نص إجابة صاحب المشروع | اختار: «إضافة مرتبطة بالكورس (موصى به)». |
| تاريخ الإجابة والتوثيق | الإجابة: 29 أكتوبر 2026. التوثيق: 29 أكتوبر 2026. |
| الحالة | متفق عليه. |
| الصياغة التشغيلية | يعرض المدرس الإضافة في صفحة الكورس كإضافة اختيارية بسعر منفصل. لا يستطيع شراءها إلا من يملك الكورس، ولا تُباع وحدها لغير المشترين. |
| القرار السابق المتأثر | لا يوجد إلغاء. يحدد شكل H-D07، ويتوافق مع H-D10 (لا بيع للدروس والأقسام منفردة). |
| الاستثناءات وما لم يُحسم | هل تُشترى مع الكورس في عملية واحدة؛ قواعد استرداد الإضافة؛ هل تنتقل مع نقل ملكية الكورس. |
| أثر البيانات والصلاحيات والمال | مقترح: كيان «إضافة» مرتبط بكورس واحد وله سعر، وشرط شراء: امتلاك الكورس. مستحقاتها تتبع قواعد المهلة والحجز (H-D03). |
| مثال قبول | عند أن يحاول طالب لا يملك كورس «أساسيات بايثون» شراء إضافة «10 تمارين محلولة»، تكون النتيجة: لا يستطيع شراءها قبل شراء الكورس. |
| المراجعة | أعدّ البطاقة Claude بطلب صاحب المشروع. لم يُحدَّد مراجع. اعتمد القرار صاحب المشروع. |
| مواضع التحديث | ملف التسليم 4.3 و5 و7؛ وثيقة المنتج 6.1؛ تخطيط البيانات D-03؛ النسخة الإنجليزية. |

## H-Q04 — المحتوى الموعود في الكورس غير المكتمل

| الحقل | القيمة |
| --- | --- |
| المعرف | H-Q04 ← القراران H-D42 وH-D43. مرتبط بـ H-D03 وO-06 وD-04. |
| السؤال المطروح | المدرس يبيع كورساً غير مكتمل (مثلاً نشر 5 دروس من 20). مستحقاته محجوزة حتى يكتمل الكورس (H-D03). كيف يُعرَّف «المحتوى الموعود» حتى نعرف متى اكتمل الكورس؟ الخيارات: منهج معلن بموعد / منهج معلن بلا موعد / المدرس يعلن الاكتمال. ثم سؤال متابعة: مرّ الموعد المعلن ولم ينشر المدرس كل الدروس، ماذا يحدث؟ الخيارات: تمديد مرة ثم استرداد / استرداد فوري / الإدارة تقرر كل حالة. |
| نص إجابة صاحب المشروع | اختار: «منهج معلن بموعد (موصى به)»، ثم «تمديد مرة ثم استرداد (موصى به)». |
| تاريخ الإجابة والتوثيق | الإجابة: 29 أكتوبر 2026. التوثيق: 29 أكتوبر 2026. |
| الحالة | متفق عليه. |
| الصياغة التشغيلية | قبل بيع كورس غير مكتمل، يكتب المدرس قائمة الدروس القادمة وتاريخاً متوقعاً للإكمال، وتظهر للطالب قبل الشراء. يكتمل الكورس عند نشر كل القائمة واعتمادها من المنصة. إذا فات الموعد، يحق للمدرس تمديد واحد بمبرر ويُبلَّغ الطلاب. إذا تأخر بعد التمديد، يحق للطالب طلب استرداد من المبلغ المحجوز، ويتوقف بيع الكورس. |
| القرار السابق المتأثر | لا يوجد إلغاء. يحدد متى يتحقق شرط «إكمال الكورس واعتماده» في H-D03. |
| الاستثناءات وما لم يُحسم | حدود تعديل المنهج بعد البيع؛ من يعتمد الاكتمال في المنصة ومدة المراجعة؛ أقصى مدة للتمديد؛ مهلة طلب الاسترداد؛ هل الاسترداد كامل أو جزئي بحسب ما نُشر (H-Q05)؛ استئناف البيع بعد الإكمال. |
| أثر البيانات والصلاحيات والمال | مقترح: حقول للمنهج المعلن (دروس مخططة) وتاريخ الإكمال المتوقع وعدد التمديدات ومبرر التمديد، وحالة «متأخر» للكورس. المبالغ تبقى محجوزة حتى الاكتمال أو الاسترداد. |
| مثال قبول | عند أن يعلن المدرس إكمال الكورس في 1 ديسمبر، ويمدّد مرة إلى 15 ديسمبر، ثم يمر 15 ديسمبر دون نشر كل الدروس، تكون النتيجة: يتوقف بيع الكورس، ويستطيع الطالب طلب استرداد من المبلغ المحجوز. |
| المراجعة | أعدّ البطاقة Claude بطلب صاحب المشروع. لم يُحدَّد مراجع. اعتمد القرار صاحب المشروع. |
| مواضع التحديث | ملف التسليم 4.3 و5 و7 و12؛ وثيقة المنتج 6.2 و9.2؛ تخطيط البيانات D-04؛ النسخة الإنجليزية. |
